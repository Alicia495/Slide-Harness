# ADR-0001: Vision モデルによるスライド品質レビュー

## Status

Accepted

## Context

テキストモデルはスライドの構造を JSON としてしか参照できず、生成済み資料の文字量、重なり、余白、図表の使い方を視覚的に確認できない。

## Decision

- モデル設定の Vision 接続テストで検証用 PNG を送信し、内容を正しく回答できたモデルだけを Vision 対応として保存する。
- Vision 対応モデルで資料を生成・編集する際は、PPTX を PNG にレンダリングして視覚レビューし、修正を最大 2 回行う。
- 画像入力、レビュー、再レンダリング、修正のいずれかに失敗した場合は資料を保存しない。
- 視覚レビューで得た最終 Deck は提案へ直接保存し、操作列を再適用して要素 ID が変わる問題を回避する。

## Alternatives Considered

- 手動で Vision 対応を指定する: 誤設定を検出できないため採用しない。
- モデル名の許可リストを使う: Azure デプロイ名と OpenAI 互換 API で信頼できないため採用しない。
- 視覚レビューを評価のみに留める: 合意した自動修正を実現できないため採用しない。

## Consequences

- 資料生成の待ち時間と AI API コストが増える。
- スライド内容を含む PNG を設定済みの AI 接続先へ送信する。
- Vision 非対応の登録済みモデルは資料生成に使えない。

## NFR Considerations

| 項目 | 採用 | 内容 / 理由 |
| --- | --- | --- |
| 認証 / 認可 | ❌ | 既存のローカルユーザー・ワークスペース境界を変更しない。 |
| キャッシュ | ❌ | 各資料の内容が異なるため、レビュー結果をキャッシュしない。 |
| 観測性 | ✅ | 失敗時は安全なエラーだけを返し、画像・キー・生応答はログに残さない。 |
| 永続化 | ✅ | Vision 能力と検証日時を `ai_models` に保存する。 |
| リトライ | ❌ | 非冪等な生成を自動再試行せず、各 API 呼び出しに明示的タイムアウトを設定する。 |
| シークレット | ✅ | 既存の AES-GCM 暗号化保存を継続する。 |
| ネットワーク | ✅ | 設定済み AI API への HTTPS / 既存接続のみを使用する。 |
| コスト | ✅ | 自動修正は最大 2 回に制限する。 |
| スケーラビリティ | ✅ | 同期リクエスト内で逐次処理し、同時生成は既存のプロジェクト版競合検出に従う。 |
| デプロイ / CI | ✅ | DB マイグレーションとユニットテストを追加する。 |
